# Vercel 풀스택 배포 준비 설계

작성일: 2026-10-04
상태: 사용자 검토 대기

## 목표

Odal BIBI의 Next.js 대시보드, FastAPI 백엔드, PostgreSQL을 Vercel 배포 환경에서 함께 운영한다. 초기 버전은 계정 가입 없이 브라우저별 비공개 세션을 제공한다. 채팅의 일정·응시료·응시자격 답변은 검색 근거가 확인되지 않으면 사실처럼 표시하지 않는다.

현재 대시보드의 추천·일정·프로필·채팅 범위를 유지한다. 이전에 승인된 Google Calendar 연동도 이어서 제공하되, 공식 시험 일정 연동이 준비되기 전에는 mock 데이터를 실제 일정처럼 노출하지 않는다.

## 결정된 방향

- Vercel의 모노레포 기능을 사용해 저장소 루트의 Next.js 프런트엔드와 `backend/`의 FastAPI 백엔드를 각각 프로젝트로 배포한다.
- FastAPI는 Vercel Python Runtime에서 실행한다. Vercel 문서상 Python Runtime은 현재 베타다.
- PostgreSQL은 별도 관리형 인스턴스로 두며 앱 연결 문자열은 `DATABASE_URL`로 설정한다. 앱 런타임은 제공자의 풀링 URL을, DBeaver는 제공자의 직접 접속 정보를 쓸 수 있도록 구성한다. DB 공급자 선택은 배포 전까지 열어 둔다.
- 계정은 추가하지 않는다. 브라우저에는 하나의 활성 세션을 두고 세션별 비밀 토큰으로 데이터 접근을 제한한다.
- 채팅의 근거 검사는 구조화된 주장·출처 ID, 코드에서 수행하는 출처 검사, 핵심 사실에 대한 별도 LLM 검증을 결합한다.
- Google Calendar 연동은 현재 `main`의 `backend/` 구조와 LLM 코드를 보존하면서 필요한 부분만 이식한다.

## 배포 구조

### 프런트엔드

- Vercel 프로젝트의 Root Directory는 저장소 루트다.
- 브라우저는 FastAPI 도메인을 직접 호출하지 않고 같은 출처의 Next.js API 프록시를 호출한다.
- 프록시는 `backend/` 프로젝트 URL과 내부 통신용 비밀값을 서버 환경변수로 보유한다. 해당 값은 브라우저 코드나 응답에 포함하지 않는다. FastAPI는 이 내부 비밀값이 없는 세션 API 요청을 거부해 브라우저가 백엔드 프로젝트를 직접 우회 호출하지 못하게 한다.
- 프런트엔드는 프로필·추천·대화의 표시와 입력을 담당한다. PostgreSQL을 직접 연결하지 않는다.

### 백엔드

- 두 번째 Vercel 프로젝트의 Root Directory는 `backend/`다. FastAPI 진입점은 `app/main.py`다.
- FastAPI는 세션 소유 토큰이 확인된 요청만 세션 데이터를 읽거나 변경한다.
- Vercel의 Python Runtime은 베타이므로 배포 전 프리뷰 환경에서 함수 시작, DB 연결, 요청 한도와 로그를 확인한다.
- `/health`는 최소 상태 확인에 사용한다. 운영 환경에서는 개발용 API 문서 노출 여부를 설정으로 제어한다.

### PostgreSQL

- PostgreSQL은 Vercel Function과 분리된 관리형 서비스에 둔다.
- 스키마 변경은 Alembic migration으로 관리한다. 앱의 시작/콜드 스타트 때 `create_all`로 스키마를 바꾸지 않는다.
- 정적 자격증명 카탈로그는 버전이 지정된 migration 또는 재실행 가능한 seed 절차로 넣는다. 시작 시와 세션 생성 요청 때 실행하는 `ensure_catalog` seed 경로는 제거한다.
- SQLAlchemy 연결 풀 크기와 대기 시간을 환경변수로 제한한다. 제공자가 connection pooler를 지원하면 앱은 풀링 URL을 사용한다.
- migration은 배포 전에 명시적으로 적용하고, 프리뷰와 프로덕션 DB를 분리한다.

## 브라우저별 세션과 데이터 접근

1. 프록시를 통한 세션 생성 요청에서 백엔드는 충분히 긴 암호학적 난수 토큰을 만든다.
2. PostgreSQL에는 토큰 원문 대신 해시만 저장한다.
3. Next.js 프록시는 응답에서 토큰을 제거하고 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키로 설정한다. 브라우저 JavaScript는 토큰에 접근하지 못한다.
4. 이후 같은 출처 요청에서 프록시는 쿠키를 읽어 FastAPI에 Bearer 토큰으로 전달한다. FastAPI는 경로의 세션 ID와 토큰 소유권을 함께 확인한다.
5. 모든 세션 하위 읽기·쓰기 경로에 같은 소유권 검사를 적용한다. 사용자가 현재 세션을 삭제하면 관련 추천·대화·일정과 쿠키를 함께 제거한다.
6. 변경 요청은 프록시에서 허용된 Origin을 확인한다. 세션 생성과 LLM 호출에는 공유 상태 기반 요청 제한을 둬 외부 사용자가 비용을 무제한 유발하지 못하게 한다.

세션은 계정이나 다른 기기로 복구되지 않는다. 브라우저 쿠키가 지워지면 해당 세션을 다시 열 수 없다. 현재 UI가 단일 대시보드이므로 브라우저당 활성 세션 하나를 기본으로 한다.

## 대시보드와 API 계약

- 백엔드 응답을 추천·일정·채팅 화면의 데이터 원본으로 사용한다. 시연용 하드코딩 응답은 실제 API 연결 후 제거한다.
- 현재 프로필 UI의 관심 분야, 공부 시간, 학습 방식, 예산 필드를 백엔드 스키마에 저장하고 추천 프롬프트에 전달한다. 기존의 경험·보유 자격증·목표 시기는 초기 UI에 없는 값으로 취급하며, 근거 없이 추정해 채우지 않는다.
- 프로필 저장은 세션을 생성하거나 소유 세션의 프로필을 갱신한다. 소유권을 검사하는 `PATCH` profile endpoint를 추가한다.
- 화면은 세션·추천·대화 내역을 API에서 불러온다. 채팅 메시지는 백엔드에 저장하고 응답의 출처를 보여준다.
- 시험 일정 provider가 아직 mock인 동안 일정 화면은 확인 대기 상태를 유지한다. 공식 출처와 확인된 원문이 없는 일정은 날짜로 표시하지 않는다.

## Google Calendar 연동

- `origin/feat/google-calendar`의 기존 구현은 현재 배포 기준으로 직접 병합하지 않는다. 해당 브랜치는 현재 `backend/` 분리보다 앞선 구조를 기준으로 해 백엔드를 저장소 루트 `app/`로 옮기고, LLM 채팅/provider와 Docker 구성을 제거한다.
- 이전에 승인된 연결·해제·일정 동기화 동작은 현재 `backend/app` 아래에 다시 적용하고 검토한다.
- 사용자가 명시적으로 연결한 Google 계정에만 동기화한다. 일정의 공식 출처가 확인된 경우에만 캘린더에 기록한다.
- OAuth `state`/redirect 검증과 최소 권한 scope를 적용한다. refresh token은 암호화해 PostgreSQL에 저장하고, 연결 해제 때 토큰과 연동 정보를 제거하며 가능한 경우 Google 권한도 revoke한다.
- Google OAuth client ID/secret, 정확한 callback URL, 토큰 암호화 키는 Vercel 서버 환경변수에 등록한다. 값은 Git과 브라우저 번들에 넣지 않는다.

## LLM 근거 검증

- 답변 생성은 일반 문단 하나 대신 주장과 출처 ID를 포함하는 구조화된 응답을 사용한다.
- 코드에서 출처 ID의 범위, URL의 검색 결과 일치 여부, 중복·미사용 출처를 검증한다. 모델이 만든 URL이나 존재하지 않는 출처 번호는 표시하지 않는다.
- 시험일·접수일·응시료·응시자격처럼 영향이 큰 사실은 인용된 검색 문맥에 대해 별도 verifier 호출을 한다. 공식 주관기관 근거가 없거나 판정이 불확실하면 그 주장을 제거하고 “미확인”으로 안내한다.
- 검증 호출 실패, JSON 형식 오류, 타임아웃도 핵심 사실에 대해 fail-closed로 처리한다.
- 검색 문서와 사용자 메시지는 지시가 아니라 신뢰하지 않는 데이터로 취급한다. 검색 결과에 포함된 프롬프트 지시를 따르지 않으며, 검색 내용이 도구 호출이나 코드 실행으로 이어지지 않는다.
- 출처 목록은 답변에서 실제 인용한 출처만 반환한다. 뉴스·블로그는 공식 근거와 구분한다.

## 순서와 완료 조건

각 단계는 독립된 변경으로 구현하고, 확인한 뒤 다음 단계로 넘어간다.

1. Alembic migration과 카탈로그 seed 경로를 준비하고 Vercel 함수에 적합한 PostgreSQL 연결 풀을 설정한다.
2. 세션 토큰·HttpOnly 쿠키 프록시·소유권 검사·세션 삭제 및 공유 요청 제한을 구현한다.
3. 구조화 답변과 하이브리드 근거 검증을 구현한다.
4. 프로필/추천/일정/채팅 UI를 실제 API에 연결하고 API 필드를 정리한다.
5. 현재 백엔드 구조에 Google Calendar 연결·해제·검증 일정 동기화를 이식하고 OAuth 토큰 저장을 보호한다.
6. `shadcn` CLI를 개발 의존성으로 옮기고 npm lockfile의 취약한 전이 의존성을 감사한다. Python 런타임을 3.12로 고정하고 `uv.lock`을 추가한다. 이어서 Vercel의 루트/백엔드 프로젝트 설정 및 환경변수 문서를 추가한다.
7. 프리뷰 배포에서 health, 세션 생성·소유권, 프로필 갱신, 추천, 채팅 출처, 캘린더 연결·동기화·해제, 세션 삭제, DB 연결을 확인한다. DB 공급자와 Vercel 프로젝트 접근 정보가 준비된 뒤 프로덕션으로 배포한다.

완료 조건:

- 브라우저 세션 토큰이 DB에는 해시로만 저장되고, 타 세션 ID만으로 프로필·추천·대화를 읽거나 변경할 수 없다.
- 검색 결과가 있어도 핵심 사실은 출처 ID와 검증을 통과해야 노출된다.
- 대시보드가 백엔드 API를 사용하고, 확인되지 않은 일정은 미확인으로 보인다.
- 확인된 일정만 명시적인 Google Calendar 연결 세션에 동기화되고, 연결을 해제하면 저장된 OAuth 비밀값이 삭제된다.
- 스키마는 재실행 가능한 migration으로 관리되고, 운영 DB 비밀값은 Git에 없다.
- 프런트엔드와 백엔드 프리뷰 배포에서 주요 흐름이 동작하고 장애 시 이전 배포로 되돌릴 수 있다.

## 대안과 위험

| 선택 | 장점 | 비용/위험 |
| --- | --- | --- |
| Next.js와 FastAPI를 Vercel 별도 프로젝트로 배포 | 기존 기술과 `backend/` 경계를 유지하고 Git 저장소를 공유 | Python Runtime 베타, 내부 프록시·환경변수·외부 PostgreSQL 설정 필요 |
| Next.js는 Vercel, FastAPI는 별도 Python 호스트 | Python API의 배포 런타임 선택 폭이 넓음 | 사용자가 선택한 단일 배포 플랫폼에서 벗어나고 서비스가 분산됨 |
| FastAPI를 Node.js API로 재작성 | 한 언어와 런타임으로 단순화 가능 | 기존 백엔드 재작성 및 검증 비용, 이번 목표보다 범위가 커짐 |

Vercel Runtime이나 관리형 DB가 준비되지 않으면 코드 수정과 배포 프리뷰 검증은 진행할 수 있어도 프로덕션 운영은 시작하지 않는다. DB 공급자와 rate-limit 저장 위치는 실제 Vercel/DB 요금제와 연결 한도를 확인한 뒤 결정한다. 세션 만료·DB 보존 기간은 프로덕션 전에 정한다.

## 프로덕션 전에 필요한 외부 설정

- DBeaver 직접 접속과 애플리케이션 풀링 접속을 지원하는 PostgreSQL 공급자 및 별도 프리뷰/프로덕션 DB
- 저장소에 연결된 Vercel 계정, 프런트·백엔드 프로젝트 ID와 서버 환경변수 입력 권한
- Google OAuth 동의 화면과 Vercel callback URL 등록, client ID/secret 및 토큰 암호화 키
- 세션 만료·DB 보존 기간, 세션 생성·채팅 요청 제한 값과 이를 공유 저장할 위치
- 공식 일정 데이터 소스가 연결되기 전까지 시험일 캘린더 동기화는 비활성 상태로 유지
